# 技術方針

## 概要

SansaSphere は、Project Sansa ecosystem 全体で利用される backend / federation / governance 基盤として構築する。

そのため、長期運用性・安全性・Traceability・高並列処理・service federation を重視した技術選定を行う。

## 基本方針

### ProjectSansa 資産継承

SansaSphere は、ProjectSansa 時代に整理された以下の設計思想を継承する。

- Traceability 重視
- Federation architecture
- Audit / provenance 重視
- Governance 重視
- 共通 backend infrastructure
- HLDocS ベース documentation

## 実装言語方針

### Rust 中心構成

SansaSphere の主要実装言語は Rust を中心として整理する。

主な理由:

- 高い安全性
- 高並列処理との親和性
- 長期運用性
- backend service との高い適合性
- federation service との親和性
- governance / provenance 管理との適合性
- 高性能 network service 構築との親和性

### 他言語利用

Rust を中心としつつ、必要に応じて他言語との併用を許容する。

例:

- infrastructure tooling
- test tooling
- migration tooling
- AI integration
- analytics

## backend architecture 方針

### ecosystem service infrastructure

SansaSphere は、XR runtime ではなく ecosystem service infrastructure として構築する。

主な対象:

- authentication
- federation identity
- account
- profile
- audit
- provenance
- governance
- VN3 license
- API infrastructure
- backend infrastructure

### federation 重視

単一サービスではなく、federation 前提で構成する。

想定対象:

- repository federation
- service federation
- identity federation
- policy federation
- governance federation

## governance / provenance 方針

SansaSphere では、governance / provenance を ecosystem-level responsibility として扱う。

主な対象:

- provenance tracking
- audit traceability
- rights metadata
- policy enforcement
- governance visibility
- VN3 license validation

## テスト方針

### Traceability 重視

以下の Traceability を重視する。

- 要件 ↔ 仕様
- 仕様 ↔ テスト
- テスト ↔ 実装
- governance ↔ audit
- provenance ↔ rights metadata

### 自動化重視

以下を重視する。

- CI/CD
- automated testing
- validation pipeline
- policy validation
- license validation

## 今後整理予定

今後、以下を整理する。

- Rust async runtime
- backend service topology
- federation architecture
- governance service topology
- provenance service topology
- VN3 license service topology
- repository federation structure
