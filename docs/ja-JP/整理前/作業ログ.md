### repository 成立経緯

SansaSphere は、当初 ProjectSansa repository 内で管理されていた backend / identity / governance 系機能を、
SansaXR repository への整理後、さらに XR runtime 非依存責務として切り出した repository として扱う。

責務分離イメージ:

- ProjectSansa
  - ecosystem 全体構想
- SansaXR
  - XR runtime infrastructure
- SansaSphere
  - ecosystem service infrastructure

そのため、SansaSphere は XR runtime 自体は扱わず、Project Sansa ecosystem 全体で利用される service infrastructure を責務とする。

### 現在の責務整理

SansaSphere は、Project Sansa ecosystem における以下を責務とする。

- federation identity

- VN3 license
- backend infrastructure

### 採用技術方針

SansaSphere の採用技術は、基本的に ProjectSansa 時代の構成を継承する方向で検討する。

ただし、主要実装言語は Rust を中心として再整理する方向で検討する。

現時点の認識:

- ecosystem service infrastructure を重視
- 高い安全性・並列性を重視
- backend / federation / governance 基盤との親和性を重視
- 長期運用可能性を重視

今後、以下を整理予定:

- Rust ベース backend architecture
- Rust async runtime 方針
- federation service 構成
- governance / provenance service 構成
- VN3 license service 構成
- test infrastructure 方針
